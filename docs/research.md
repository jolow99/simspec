# Phase 0 research: a typed spec language + thin runtime for LLM multi-agent game studies on memo

Date: 2026-10-16. Everything below was verified against primary sources (source code, full papers, official API docs), not abstracts. Long-form notes with verbatim definitions are in `docs/research/` (one file per source). Where the brief's assumptions were wrong, this is called out in a dedicated section at the end.

## 0. Headline findings

1. **memo is a table compiler, not a simulator.** A memo computes an array over declared finite axes by exact enumeration; it has no sampling, no mutable state, no loops, no strings. Time is recursion over a static parameter, histories must be enumerated into a `domain`, and the set of agents is fixed in the source text. So the game loop, RNG, logs and free-text slots must live outside memo, and memo is called per decision point for policies and beliefs. This is workable (tested) and is the right division of labour.
2. **This repository is stale.** It is a fork of `kach/memo` at version 1.2.3 (Sept 2025). PyPI `memo-lang` is at 1.3.2 (14 Oct 2026) and 1.2.3 does not run on current JAX (0.11): `demo/test.py` fails at the first FFI call. 1.3 adds things we need (array-valued "exotic" parameters, `forgets_about`, multiple return values, keyword args). The new library should depend on `memo-lang>=1.3.2`, not the vendored copy. Decision needed from you (see §9).
3. **ContractSim is narrower and more precise than the brief.** Exactly two players, an asymmetric accept protocol, a closed four-clause contract vocabulary that exists only in an offline LLM translator, an alternating 11-week horizon, and rational baselines that are exact constrained-MDP solvers. No code is released. Full formalism obtained from the TeX source.
4. **The norms paper's rule grammar is small and enumerable**, and its code is released (a Melting Pot fork). Prohibitions = (action class, predicate on next state); obligations = (trigger, discharge, deadline). Induction is mean-field Bayes with a bounded-compliance likelihood built from a planner's Q-values with and without the rule. The environment is a 23×22 Melting Pot substrate, not a toy grid.
5. **Concordia's useful idea is the engine↔game-master protocol** (five typed questions: observe, who acts, action spec, resolve, terminate) and its scene machinery; everything else (string state, LLM in the control path, no seed, threads) is what we are avoiding.
6. **Decision-model APIs exist as described and always return full distributions** for choice/score questions (TypeSafe Jev `/v1/systemone`, OpenAI `/v1/decisions`, plus Perplexity, Cloudflare, Microsoft, Ollama, llama.cpp, vLLM). Two wire formats cover the ecosystem. Anthropic and Google have no native distribution-returning endpoint; adapters verbalise probabilities. Calibration is unproven; option order matters.
7. **Both games fit one shape**: a finite-horizon partially observable stochastic game with typed state, per-player observation functions, finite action sets, trajectory-level payoffs, and `Rule`s that are pure functions of per-agent histories (with optional sanction/payment hooks). ContractSim adds a variable-length cheap-talk phase with a free-text slot; the norms game adds a hypothesis space of rules and a belief-updating agent. The spec language needs phases/protocols, not just a transition function.

## 1. memo (verified from source, Handbook v1.2.0, the OOPSLA'25 paper, and experiments)

### Provenance
- Paper: Chandra, Chen, Tenenbaum, Ragan-Kelley, "A Domain-Specific Probabilistic Programming Language for Reasoning about Reasoning (or: a memo on memo)", PACMPL 9 (OOPSLA2), 2025, DOI 10.1145/3763078. Read from the OSF preprint PDF (osf.io/pt863). It is not on arXiv.
- Companion paper: "Theories of Mind as Domain-Specific Languages of Thought" (Chandra, Ragan-Kelley, Tenenbaum, Saxe), arXiv 2609.19598, Sept 2026. Read the HTML version.
- Source: this repo is `kach/memo` at **1.2.3** (last commit 2025-09-14). PyPI `memo-lang` is at **1.3.2** (2026-10-14); diffed against the repo.

### How models are declared
- `@memo def f[x: X, y: Y](a, b): stmts; return expr`. Square-bracket "axes" are the dimensions of the returned array; parenthesised parameters are *static* scalars passed through unchanged (recursion depth, temperatures). Since 1.3, a parameter annotated `p: ...` is an "exotic" parameter: a JAX array that may only be passed straight into FFI calls.
- Statements: `a: chooses(x in D, wpp=e)` (aliases `given/draws/assigned/guesses`; `to_maximize`/`to_minimize` for argmax), `a: thinks[ b: ... ]` (nested frame), `a: observes [b.x] is c.y` (condition; sugar `sees/hears`), `a: observes_that [bool]`, `a: observes_event(wpp=p)` (soft factor), `a: knows(x, b.y)` (push a variable into a frame), `a: wants(u=expr)` + `EU[u]`, `a: snapshots_self_as(past_a)`, `Predict[e]`, `imagine[ stmts..., expr ]`, `INSPECT()`. New in 1.3: `a: forgets_about(x)`, `a: has_theory(CHILD|NO_THINKS|NO_KNOWS|NO_WANTS)` developmental variants, multiple `return`s, keyword args in memo/FFI calls, `cost @ f(...)` with time/space/size metrics.
- Expressions: literals, params, choices, `a.x` / `a[e]`, `E[]`, `Pr[]`, `Var[]`, `H[]`, `KL[]`, arithmetic/logic, `e1 if c else e2`, FFI calls to `@jax.jit` scalar functions, memo calls `g[x, b.y](params)`, inline Python `{expr}`.
- Abstract syntax (paper Fig. 4): `s ::= a: chooses(x in D, wpp=e) | a: observes [b.x] is c.y | a: thinks[s*]`; `e ::= l | op(e*) | x | a[e] | E[e] | m[a.x*](l*) | imagine[s*, e] | cost @ m(l*)`. Everything else desugars.

### Domains allowed
- Any Python object that is iterable with `len()`, used as `jnp.array(D)`: lists, `IntEnum`s, 1-D JAX/NumPy arrays (`np.arange`, `np.linspace`), and `memo.domain(f1=n1, f2=n2, ...)`, a mixed-radix packing of a product of finite ranges into one integer (`D(f1=..)`, `D.f1(z)`, `D._tuple(z)`, `D._update(z, f1=..)`). Values reach FFI functions as scalars.
- Everything is **finite and discrete**; continuous quantities must be discretised (paper §5). No strings and no structured values: structure is encoded via `domain` or via lookup tables inside `@jax.jit` functions.

### How it compiles (verified in `core.py`, `codegen.py`, `parse.py`)
- The decorator reads the function source with `inspect.getsource`, parses it with Python's `ast`, and translates to a memo AST. So memos **must live in a real file** (not the REPL) and the sugar is fixed by the parser.
- The compiler walks statements with a tree of `Frame`s (observer root → agent → agent's model of another agent ...). Each frame tracks `choices: (who, id) -> Choice(tag, idx, known, domain)`, `conditions` (aliases created by observes/knows), `goals`, and an `ll` symbol naming the frame's joint-probability array.
- Each new choice in any frame allocates a **fresh global array axis**; arrays broadcast against each other. `chooses` emits `jnp.array(D).reshape(-1,1,...,1)`, evaluates `wpp`, normalises along the new axis (softmax trick if `exp(...)`, argmax mask for `to_maximize`), and multiplies into the frame's `ll`. `observes` renormalises `ll` over unknown axes. `E[e]` is `marg(ll * e)` over the unknown axes. Posteriors of the form `Pr[x == b.y]` are optimised to a diagonal collapse.
- Static semantics: every expression carries `known` and `deps`; a `wpp` must be known to the chooser ("no mind control"), queries `a[e]` must be known to `a` ("no mind reading" unless wrapped in `E[]`), returns must be known to the observer. Errors are raised at compile time with source locations.
- Code generation produces Python text (`def _make_f(): @jax.jit def _jit_f(...): ...`) and `exec`s it in the caller's globals, or into a dynamically created module via `make_module(name)` + `@memo(install_module=m.install)`. Memo calls and `if static_cond:` branches run in the un-jitted wrapper; only the array math is jitted. Recursion depth `t` is therefore a Python-level loop over separately jitted calls with constant shapes: JIT compiles once per memo, not once per `t`.
- `@memo(cache=True)` wraps the generated function in `functools.cache`, keyed on the static parameters. This is what makes value-iteration-style recursion linear instead of exponential.

### Limits for multi-step environment loops (verified by experiment; scripts in `docs/research/experiments/`)
1. **memo computes tables, not trajectories.** No sampling, no RNG, no mutable state, no loop construct. Time is recursion over a static parameter (`Q[s,a](t-1)`) and histories must be **enumerated into a domain** (e.g. `H = domain(a1=3, a2=3, ...)`, as in `demo-i-pomdp`). A 3-round, 2-action, 2-player history is already 3^6 = 729 states. The environment loop must live outside memo, in Python, and call memo for per-state policies/beliefs. Tested: a 3-round repeated game with a hidden opponent type, p1 as a memo level-1 planner that conditions on history via `observes_event(wpp=likelihood(type, h))`, sampled step by step from Python: compile+run 0.7 s for |H|×|A| = 729×2, whole loop 1.2 s.
2. **Static shape**: "only supports control flow where the sequence of choices is known statically" (paper §5). A variable-length negotiation with free text cannot be a memo axis; only a finite abstraction of it can.
3. **Parameters are scalars** (checked at runtime by `check_scalar_param` in 1.3). Arrays can be passed as exotic `p: ...` parameters, but then `cache=True` fails (`unhashable type: ArrayImpl`), so memoised recursion with array parameters is impossible. Tested workaround: put tables in the globals of a generated module and keep only scalars as parameters; regenerate the module per game instance. Depth-50 recursion with cached globals: 0.11 s.
4. **Memory is the product of all axes in a frame tree** (every choice in every nested frame is a global axis). A 2-level nested frame with |S|=200, |A|=5, |Ty|=4 compiles and runs in < 0.2 s. Blow-ups come from histories, not from recursion depth.
5. **FFI functions must be scalar-in, scalar-out `@jax.jit` functions** (vmapped internally). Transition, payoff and observation functions for our games must be written in this form, typically as table lookups into JAX arrays. (1.2.3's `isinstance(f, jax.lib.xla_extension.PjitFunction)` check is what breaks on JAX ≥ 0.6; 1.3.2 removed it.)
6. **No first-class agents**: agent names are identifiers in the source; the set of agents and the nesting are fixed at compile time. A spec with N players therefore has to *generate* memo source text (`make_module` plus a file on disk, since `inspect.getsource` is required). Verified working.
7. **Observation is modelled by `observes [b.x] is y`** between choices already modelled, and the compiler statically prevents using an unobserved variable. This is exactly the guarantee we want to inherit: if the spec's observation function is compiled into `knows`/`observes` statements, an agent's memo policy cannot read hidden state.

### What memo can and cannot express for our two games
- Can: finite-horizon (PO)MDP planning by value iteration (built-in demos: MDP, POMDP in belief space, I-POMDP investment game with enumerated histories); level-k / cognitive-hierarchy reasoning about other players (Schelling, ultimatum); Bayesian inference over hidden types from observed actions; softmax policies with exact probabilities; expected utility of hypotheticals via `imagine`; information-theoretic quantities; gradients for fitting.
- Cannot natively: sample trajectories; represent natural-language messages or contracts (only an index into an enumerated finite contract space); run a 50-round negotiation; mutate state; handle continuous money and prices except on a grid; let the set of agents vary at run time.
- Consequence: memo is the **baseline/belief engine**, invoked per decision point with the current finite information state as an axis index; the spec runtime owns the loop, RNG, logs, and free-text slots.

### The "Theories of Mind as DSLs" paper
It is about human theory of mind, not LLMs: memo constructs are treated as the syntax of an intuitive theory; `knows` is more primitive than `thinks`; `wants` is continuation-based (looks ahead in the program). Its one LLM component is a prototype "modular social agent" where an LLM supplies world knowledge and memo does the Bayesian computation. That is the same division of labour we propose (LLM proposes, memo computes). It says nothing about norms, contracts, or extended interaction. Its stated limitations are about theory scope, not about the language.

## 2. Game A: ContractSim (arXiv 2608.10475, verified from the TeX source)

Sajja, Kleiman-Weiner, Zimmermann, Zhi-Xuan, "Evaluating Rational Contracting in Natural Language", v1 11 Aug 2026, AAAI-27 format, 9 pp + 34 pp appendix. Full text obtained from the arXiv TeX source and the PDF. **No code or data is released.** Verbatim definitions are in `docs/research/contractsim.md`.

### Formalism
- **Negotiation-performance game** `G = (I, Θ, Ω, N, P)`: players `I = {1,2}`, private types `Θ`, contract space `Ω`, negotiation game `N = (M, Ω, α)` (message space `M`, protocol `α: M* → Ω | ⊥ | ⊤`), performance game `P` = a partially observable stochastic game `(S, (A_i), (O_i), T, (O_i), L, (u_i))` with **trajectory-level** utilities `u_i(τ; θ_i)` and policies `π_i(a_{i,t} | o_{i,1:t}, θ_i, ω, h)`.
- **Contracts are constraints on joint policies**: `ω` induces `C^ω: T → {0,1}` on trajectories and a tolerance `ε`; the compliant set is `Π^ω = {π : P_sat(π, C^ω) ≥ 1−ε}`, `P_sat = E_τ[C^ω(τ) | π]`, `ε = 0.05`. `C^ω` decomposes into **role-specific absorbing prefix indicators** `C^ω_{i,t}(τ_{≤t})` (once a role breaches it stays breached); `C^ω(τ) = ∏_i C^ω_{i,L}`.
- **Rational baselines**: Rational Complier `RC_i = argmax E[u_i | ω, π_i, π^ref_{-i}]` s.t. compliant; Rational Exploiter `RE_i = argmax E[u_i | ω, π_i, RC_{-i}]` (implemented only as *non-engagement*: pay 0 / order 0); Rational Conditional Complier `RCC_i` = RC until a counterparty violation is observed, then best response to RE (grim trigger). Contract value `U_i(ω) = E[u_i | ω, π^RCC]`. Rational-negotiation upper bound: full-information Pareto frontier `ω*(η) = argmax U_i s.t. U_{-i} ≥ η, P_sat(π^RCC) > 1−ε`.
- RC Supplier is a **finite-horizon constrained MDP solved by exact backward DP** over `(inventory, cash, contingency memory, observed price)`, lexicographic: among orders with `P̂_sat ≥ 0.95` maximise value, else maximise `P̂_sat`; production uses a fixed heuristic (prefer full fulfilment, then credited value with 4:2:1 weights, then minimal ingredient use). Deterministic policies only.

### ContractSim instance (Catering; Hotel Cleaning and AI Hosting are relabelings ×100 / ×1000)
- Two players: **Customer** (budget B=200, private per-unit values `v_d`, minimum 1 of each product per production week, substitution 1 Pizza = 2 Pasta = 4 Soup) and **Supplier** (capital $20/$40, recipes `O1 = I1+I2+I3, O2 = I1+I2, O3 = I3`, private price/receipt/spoilage laws). Supplier starts with empty inventory; inventory cap 10 per input; order cap 12 per input per round.
- **Horizon L=11, alternating**: payment weeks 1,3,5,7,9,11 (Customer chooses `M_w ∈ ℕ`, ≤ remaining budget), production weeks 2,4,6,8,10 (Supplier). Week 11 is a terminal payment.
- **Production week, in order**: (1) spoilage `s_{w,x} ~ S_x` on carried inventory; (2) Supplier observes realised prices `p_{w,x} ~ P_x` and orders `o_{w,x} ∈ {0..12}` subject to cash; (3) receipt `r_{w,x} ~ R_x(·|o)` (pay for ordered, not received); (4) cap 10 applied, excess lost but paid; (5) production plan (any feasible integer output vector) and immediate delivery; (6) prices redrawn. Six environments: {no, low, high} stochasticity × {values 12/6/3 + $20, values 20/10/5 + $40}. Low: prices `M 1(2/3)|3(1/3)`, `B 1|2`, `T 2|3`; receipt `U{⌊3x/4⌋..x}`; spoilage `U{0,1}`. High: 50/50 prices; receipt `U{⌊x/2⌋..x}`; spoilage `U{0,1,2}`.
- **Observation**: both see the contract, payments, deliveries; only the Supplier sees inventory, prices, spoilage, receipts, balance; the Customer sees total paid and remaining budget. Types are private. During negotiation dialogue and proposals are public, private prompts hidden.
- **Payoffs**: `U_Cust = B + Σ_w Σ_d v_d q'_{w,d} − Σ_w M_w`, `U_Supp = Σ_w M_w − Σ_w Σ_x o_{w,x} p_{w,x}`; disagreement gives B and 0.
- **Contract schema**: free text during negotiation; translated offline (Gemini 3.6 Flash) into a closed schema `C^ω = (prices p_d, delivery schedule q_{w,d} over 5 production weeks, payment schedule M_w over 6 payment weeks, κ ⊆ {substitution, grim_trigger, payment_deduction, rollover} with params)`. Clause semantics: payment deduction (deduct unit-price value of a shortfall from the next payment; two consecutive shortfalls = violation), rollover (carry a deficit ≤ 2, must cure next round), substitution (above-minimum output credited at 4:2:1), grim trigger (cease performance after a violation; supplied implicitly as solver fallback if absent). Text outside the vocabulary is ignored. "Parse-complete" requires all 3 prices, 5 quantity rows, 6 payments.
- **Negotiation protocol**: ≤50 rounds, each round = Customer turn then Supplier turn; turn output JSON `{response, contract | accept | terminate}`; a proposal replaces the active proposal; **only the Customer can accept, and only the Supplier's proposal from the immediately preceding round**; proposing and accepting in one turn is forbidden; either side may terminate; round limit = disagreement.
- **Metrics**: negotiation: `P_sat`, gains `G_i = U_i(ω) − u_i(⊥)`, mutual benefit, proposal feasibility, acceptance regret, contingency count, occupancy-based completeness, distance to the Pareto frontier. Performance (180 synthetic optimiser-generated contracts × roles × 3 LLMs × {RC, RE, RCC} counterparties = 4,860 games): utility, compliant utility, ex-post regret vs re-simulated RCC (same seed), defection / unilateral / reciprocal defection, compliance / conditional / exploited / tit-for-tat compliance. No fairness metric.
- **Harness as described**: Concordia agents with an append-only provider conversation + top-5 recalled observations; JSON actions with up to 3 corrective retries then default-to-zero; offline translation with validator and cache; exact DP solvers; forward occupancy push for completeness.
- **Headline results**: 159/162 agreements; mean `P_sat` 90%, 77% above 0.95; 85% mutually beneficial; zero contingency clauses unless prompted; LLMs beat RCC utility only by defecting (GPT-5.6-Sol customer defects in 84% of games); "prohibition" and "institutional incentive" prompts cut defection.

### Implications for the spec language
- Two phases with different shapes: a **variable-length cheap-talk protocol with free-text slots** (dialogue, contract text) and a **finite-horizon POSG with typed state**. The spec needs a phase/protocol construct, not just a transition function.
- `Rule` = the contract constraint `C^ω` as role-specific absorbing prefix indicators plus tolerance `ε`; sanctions are *behavioural* (counterparty switches policy), not environmental. The four contingency clauses are a small closed Rule vocabulary worth typing directly.
- A separable **NL → Rule translation** component (LLM-proposed, validated, cached) is needed; it is the "Large Language Bayes" pattern with one or several candidates (§5).
- Baselines need **re-simulation with a swapped policy and a fixed seed** plus per-week obligation/fulfilment logging; the log must record the RNG stream per step.
- The state is small enough for exact enumeration only because of the caps (10/12). A memo value iteration over `(inventory ≤ 11^3, cash ≤ ~200, memory, price scenario)` is roughly 10^6–10^7 cells per week: feasible but at the edge; a plain-JAX DP may be preferable for RC, with memo reserved for level-k reasoning and type inference. To be measured in Phase 1.

## 3. Game B: norm-augmented Markov games (arXiv 2402.13399, verified from the PDF and the released code)

Oldenburg & Zhi-Xuan, AAMAS 2024. Code at `github.com/ninell-oldenburg/social-contracts` (MIT; a vendored fork of Melting Pot 2.0 with a new `rule_obeying_harvest` substrate; cloned and read). Verbatim definitions are in `docs/research/norms.md`.

### Formalism
- **Norm-augmented Markov game**: a Markov game `(S, A_i, T, R_i, γ, H)` plus a space of norms `𝒩`, each a history classifier `ν: H → {0,1}` (1 = violation). Each agent has a per-norm prior `P_i^0(ν)` (probability the norm is complied with by everyone with frequency ≥ 1−ε), independent across norms, a violation cost `C_i(ν)`, and a **norm-augmented reward** `R'_i = R_i(s,a,s') − Σ_N P_i(N|h) Σ_{ν∈N} C_i(ν) ν(h)`. Defines subjective/objective normative equilibria and stability.
- **Rule grammar** (first-order predicates over state): Prohibition `⟨Prohib, Post⟩`: violated if an action in `s[Prohib]` leads to `s'` with `s'[Post]`. Obligation `⟨Pre, Post, τ⟩`: violated if `Pre` held at `t−k` and `Post` never held within `τ` steps. Both reduce to history classifiers. The five practised norms: P1 "don't pick up an apple if fewer than 3 apples around", P2 "don't harvest on foreign property", O1 "farmer: pay the cleaner after 30 unpaid steps", O2 "cleaner: clean when dirt > 0.3", O3 "egalitarian: clean when dirt > 0.45", τ = 20.
- **Planning**: RTDP (depth 20, γ=0.9, re-plan every 2 steps) with prohibitions as **action masks + cost 1** and obligations as **goal switching** (shortest path to `Post` with reward 1), FIFO obligation queue; under uncertainty either threshold (`P ≥ 0.95`) or Thompson-sample a norm set every K steps.
- **Bayesian rule induction**: assume others are norm-compliant planners who know the norms; mean-field posterior with one Bernoulli belief per norm (prior 0.05); per observed other-agent action, `P(a | ν) = p_obey · Boltzmann(Q^ν)(a) + (1−p_obey) · Boltzmann(Q^∅)(a)` with `p_obey = 0.9`, temperature 1, uninformative when the norm is not applicable in that state; obligations only yield evidence when the goal is one step away.
- **Hypothesis space**: 68 norms (Table A1) enumerated from feature × comparator × threshold grids (`DIRT_FRACTION > {0.3..0.6}`, `SINCE_AGENT_LAST_PAID > {10..30}`, `NUM_APPLES_AROUND < {1..8}`, `ORIENTATION`, `CUR_CELL_HAS_APPLE`, `CUR_CELL_IS_FOREIGN_PROPERTY`, `RIOTS`) × roles × action class `MOVE`, filtered by hand-coded feasibility rules. In code, rules are **Python boolean expressions over an observation dict** compiled with `ast`, and `τ` is a global constant.

### Environment (as implemented)
23×22 Melting Pot gridworld combining Commons Harvest (density-dependent regrowth `[0.02,0.05,0.07,0.09]` by neighbour count, desiccation), Clean Up (river dirt spawns with p=0.2; pollution throttles regrowth between dirt fractions 0.1 and 0.7), Territory (5×5 claimed property per agent, steal records). 12 actions (noop, 4 moves, 2 turns, zap, clean, claim, eat, pay). Roles cleaner / farmer / free ("egalitarian") / learner, shown by sprite. Rewards: apple 1, action cost 0.01, violation cost 1, obligation reward 1, zap penalty 15. H = 300. Learners have **full observability**; rule features are derived in Python from a map-sized `SURROUNDINGS` tensor. Other agents are modelled as static obstacles in each agent's forward model.

### Experiments and metrics
13 runs per condition. (1) Passive learning: 3 experienced + 1 learner; per-norm posterior trajectories; precision/recall at P ≥ 0.95 (recall 0.83 at 300 steps with 5 norms, precision 0.32: over-generalisation and overlapping thresholds because mean-field cannot explain away). (2) Social outcomes: cumulative collective reward and desiccated-field ratio with vs without norms. (3) Intergenerational: 6 agents with lifespans 10..600 and prior reset at rebirth; prohibitions transmit at lifespan ≥ 50, obligations are collectively forgotten. (4) Emergence: 3 learners, none seeded; arithmetic vs geometric mean belief; mostly "silly" norms emerge. Sanctions (a "zap violators" meta-obligation and an expected-punishment term) exist in code but were disabled.

### Implications for the spec language
- `Rule` must support **prohibitions on (action, next-state predicate)** and **obligations (trigger predicate, discharge predicate, deadline)**, grounded in named typed observation features with thresholds, and enumerable from a feature grammar. ContractSim's four contingency clauses fit the same mould (payment deduction = obligation with a monetary discharge; grim trigger = conditional release from obligations; rollover = obligation with deadline extension).
- Compliance checking is a **pure function of a per-agent history**; sanctions and payments are separate optional hooks (environmental: zap, payment deduction; behavioural: RCC switch).
- A norm-inference agent is a Bayesian filter over a finite rule space whose likelihood is a policy model. memo can express exactly this likelihood (`observes_event(wpp=mixture)` with `Q^ν` and `Q^∅` tables) as long as the per-step local decision problem is finite; RTDP over the full gridworld is not a memo program. The "rational baseline via memo" for Game B should therefore be scoped to a reduced state abstraction (position + local features) or to the belief update only. To be decided in Phase 1.

## 4. Concordia (v2.4.0, verified from source and both papers)

Details and verbatim type contracts are in `docs/research/concordia.md`.

### What it is
Everything is an `Entity{name, act(ActionSpec) -> str, observe(str)}`. An entity is a bag of `ContextComponent`s (`pre_act/post_act/pre_observe/post_observe/update`, all returning strings for the prompt) plus one `ActingComponent`. The **Game Master is itself an entity**; the `Engine` (`Sequential`, `Simultaneous`, `Asynchronous`) drives it by calling `gm.act()` with GM-only output types `MAKE_OBSERVATION, NEXT_ACTING, NEXT_ACTION_SPEC, RESOLVE, TERMINATE, NEXT_GAME_MASTER`. `SwitchAct` routes each to a component (`MakeObservation` with an `ObservationQueue`, `NextActing*`, `NextActionSpec*`, `EventResolution`, `Terminate*`, `SceneTracker`, `PayoffMatrix`, `Inventory`, `WorldState`) and falls back to the LLM when no component answers. `ActionSpec` is the only typed action surface: `output_type ∈ {FREE, CHOICE, FLOAT}` + options + tag; actions are always strings. Scenes (`SceneTypeSpec`, `SceneSpec`: participants, rounds, premise, action spec, GM) are the closest thing to a declarative game spec.

### Papers
- 2312.03664 ("Generative agent-based modeling with actions grounded in physical, social, or digital space"): four-equation sampling formalism (no POMDP); "grounded variables tracked in Python, rendered to language".
- 2507.08892 is titled **"Multi-Actor Generative Artificial Intelligence as a Game Engine"** (not a contest paper; the contest paper is 2512.03318). It argues for entity-component composition, one action per step, GM as a configurable entity, and an Evaluationist / Dramatist / Simulationist typology. No formal model and no logging discussion.

### What a harness has to do, per Concordia, and what we borrow
| Duty | Concordia | Borrow | Do differently |
|---|---|---|---|
| Engine loop | `while not terminate: next_gm → observe → next_acting → act → resolve → log → checkpoint`; sequential / simultaneous / async | The closed enum of five engine→GM questions; sequential vs simultaneous as the two engine kinds; `max_steps` + explicit terminate; step callbacks | Deterministic, single-threaded, seeded; `resolve` returns a typed transition, not a string; validate actions in the engine |
| Agents | `Entity{act, observe}` + components; prefab + `InstanceConfig(prefab, role, params)` | Tiny agent surface; `get_state/set_state`; prefab configs | Type `act` as `Observation → distribution over Action`; rational/best-response policies as first-class agents |

| Scenario config | `Config(prefabs, instances, premise, max_steps)`; scenario registry with focal/background roles; `puppet` test scenarios | Scenes as phases; registry; focal/background; deterministic puppet tests | Fully declarative (no callables in config) |

| Metrics | Payoff callables, questionnaires, LLM autoraters over the log | Autorater as a separate pass over a frozen log | Payoffs/metrics from typed state; exact baselines possible |
| Replay | `step_n_checkpoint.json` resumes but is explicitly not deterministic; no run seed; threads | `get_state/set_state` discipline | Seeded RNG threaded through everything; recorded model I/O so a run replays with a "replay model" |

### What we deliberately won't copy
String-typed state and actions; LLM-maintained grounded variables; LLM in the control path by default; threads in the loop; global RNG; callables in config; metrics by grep; the dependency footprint (pandas, matplotlib, reactivex, sentence-transformers, a visual server, an MCP tool layer).

### The common contract
- Input: one `state` (string | JSON) shared by a set of independent typed questions. `choice` returns argmax + distribution + confidence; `score` returns per-level distribution + mean index; `noul/predicate` returns P(true). No generated text; billed on input tokens only (Jev $0.042/M, OpenAI $0.10/M, Perplexity $0.02/M). Latency 70–500 ms (Jev claim), ~150–800 ms (OpenAI, secondary).
- Two wire formats cover the ecosystem: **TypeSafe-style** (`state`, `questions` map, `criteria`) used by Jev, Perplexity, Cloudflare Workers AI (Clef), Microsoft Foundry, Ollama 0.35, llama.cpp, vLLM, OpenRouter; **OpenAI-style** (`input`, `questions` array with `choices[{value,description}]`, answers array). Gateways: LiteLLM (both, with a documented field map), Vercel AI Gateway (three surfaces), Portkey (auto-detect), agentgateway, llmgateway.io. Cloudflare AI Gateway: no evidence of support.
- Normalised internal answer type for our adapter: `Choice{choice, probs: dict[str,float], confidence|None} | Score{...} | Bool{p_true} | Refusal`, plus `meta{model, latency_ms, usage, raw, native_distribution: bool}`. Renormalise after rounding in our layer only.
- Calibration evidence is thin and partly negative: JevOut (arXiv 2609.30243) flips 61–73% of correct decisions with benign context additions; a CSS annotation study finds the decision model trails LLMs on 14/15 tasks at ~44× lower cost; OpenAI `choice` was over-confident and order-sensitive in a community test; Microsoft recommends randomising option order; llama.cpp/vLLM are explicitly uncalibrated (logprob softmax). Consequences for the adapter: always keep the full distribution; permute option order across repeated calls and average; treat `confidence` as dispersion, not accuracy; log the resolved model version.

### Large Language Bayes (Domke, arXiv 2504.14025, NeurIPS 2025)
The LLM is a prior over formal programs `p(m | t)`; the PPL gives `p(z, x | m)`; the posterior over the quantity of interest marginalises programs with weights `p(m | x, t) ∝ p(m | t) p(x | m)`. Recipe: sample N programs, run inference on each, bound the log evidence (importance-weighted bound from a moment-matched Gaussian), weight by `exp(bound)`, mix. Mapped to our setting: `t` = contract/rule text + observation schema + action set; `m` = a candidate typed `Rule`; `x` = observed (observation, action, outcome) triples or rulings; `p(x | m)` = a noisy-channel likelihood for deterministic rules; the action distribution is the weighted mixture over candidates. Decision-model `noul` questions ("does rule R permit action a in observation o?") are cheap likelihood evaluators inside this loop. Caveats: near-duplicate proposals waste compute (dedupe by behavioural signature on a probe set); weights are sensitive to likelihood temperature; a narrow proposal prior silently drops the right rule.

## 6. Other prior art (verified against official docs where marked; full survey in `docs/research/prior_art.md`)

### LangGraph
Graph/state-machine orchestration with a checkpointer (`thread_id` + `checkpoint_id`, channel values/versions, parent pointer, `metadata.step/source`), time travel by `update_state` at a historical checkpoint, and `interrupt()` for human-in-the-loop. Borrow: the addressable per-step checkpoint as a fork point (`episode_id`, `step`, `parent`); "fork = write a modified state at step N and continue" as the semantics of counterfactual replay (replay from step 7 with a different contract in force); the explicit distinction between replay-by-recompute (agents are called again) and replay-by-readback (the log suffices), which LangGraph only has the first of; persist each agent's action as soon as it is produced in a simultaneous round. Do not borrow: the Pregel/reducer state model (order-dependent merging is what a game spec must forbid), `interrupt()` re-execution, `TypedDict` + reducers as the state typing scheme.

### Inspect AI
The best log reference. Per-sample typed event stream: `ModelEvent(model, requested_model, input, tools, config incl. seed/temperature/logprobs/top_logprobs, output incl. logprobs, call = raw request/response, cache, retries, usage)`, `StateEvent`/`StoreEvent` as JSON-patch diffs, `ScoreEvent` and `ScoreEditEvent` (scores are mutable annotations on an immutable transcript, which matches "metrics computed offline"), spans, header-only and streaming readers, cache key = messages + config + tools + epoch + model@version, and the agent-bridge idea (route any framework's model calls through the runtime so they are logged). Do not borrow: `Task/Dataset/Solver/Scorer` (the unit is one model on one prompt; ours is an episode with N agents), the `.eval` binary container.

### clembench
Per-episode three-file split: `interactions.json` (game events: `from`, `to`, `action.type ∈ send message / get message / parse / invalid format / error / metadata`), `requests.json` (raw prompt/response objects), `scores.json` (turn and episode scores; aborted ⇒ NaN). Explicit parse / invalid-format / aborted semantics are exactly what offline metrics need.

### Environment suites
- **OpenSpiel** has the cleanest game semantics: `GameType(dynamics, chance_mode, information, utility, reward_model)`, `kSimultaneousPlayerId` and a chance player, `legal_actions(player)`, `information_state_string` vs `observation_string`, `rewards()` vs `returns()`, `history()` + `serialize()` = exact replay. Imperative C++/Python state classes; no declarative typed state; no norms.
- **PettingZoo** has the cleanest loop shape: AEC (`agent_iter`, `last()`) vs Parallel (`step(dict)`), `possible_agents` vs `agents`, `action_mask`, `TerminateIllegalWrapper`, `reset(seed)`.
- **Melting Pot**: substrates + scenarios with focal vs background populations as the evaluation protocol; simultaneous moves only; Lua components (the norms paper's environment is one of these).
- **Gymnasium spaces**: overkill for finite typed sets, but `sample(mask=)`, `contains`, `to_jsonable/from_jsonable`, `seed` are the right method set for our domains.

### LLM multi-agent game frameworks 2023–2026 (about 30 surveyed)
GovSim (common-pool resource with discussion rounds; bespoke Hydra harness, no log schema), NegotiationArena (no shared game abstraction), GTBench (OpenSpiel `observation_string` + `legal_actions` as the LLM prompt basis; glue rebuilt), MAgIC, SOTOPIA (`EpisodeLog` with turn-indexed `(sender, receiver, text)` messages, private `to=` addressing, LLM-judged rewards), TextArena (observation = list of `(sender_id, message, ObservationType)` entries addressed to a player; untyped `game_state`), AgentVerse (environment = order × visibility × selector × updater × describer rules, a good checklist), CAMEL, AutoGen (maintenance mode), MARBLE, Welfare Diplomacy (exploiter baselines), LLM-Deliberation (private reasoning vs public message logged per step), AI-Economist Foundation (`dense_log = {world, states, actions, rewards}` per step; namespaced observation keys; masks), GLEE, **CoopEval** (ICML 2026: PD / trust / public goods with cooperation-sustaining mechanisms including outcome-conditional contracts; conceptually the closest to first-class contracts, but a benchmark with mechanisms as prompt variants, code not yet released), SidConArena (three-phase bargaining → production → auction), SPIN-Bench, DSGBench, Werewolf Arena, GAMA-Bench, plus norms-specific papers (arXiv 2510.14401, 2409.00993, 2408.12680) none of which releases a reusable norm-aware harness. Cross-cutting trajectory formats (Harbor ATIF v1.7, NVIDIA ATOF) are single-agent and tool-use-centric: no joint actions, per-agent observation, or payoffs; worth aligning field names (`step_id`, `source`, token/cost metrics) for export only.

### agentmodels.org / WebPPL and memo
In agentmodels.org, multi-step behaviour lives *inside* planning (`simulate` recursing through `transition` and the opponent's `act`); there is no outer environment loop. memo's demos follow the same pattern (recursion over a horizon `t` with state, belief, or encoded history as an axis). No published project wraps memo in an environment loop or an LLM harness. The spec must export integer-coded domains, jittable transition/payoff/observation functions, and an information-state encoding so memo agents can be generated.

## 6c. Thin layer over existing tools? Hands-on evaluation

Both candidates were installed in an isolated environment (`inspect-ai` 0.3.281, `langgraph` 1.2.15; together 102 packages, 339 MB) and probed with scripts in `docs/research/experiments/`.

- **Inspect AI as the log**: an `EvalLog` with one `EvalSample` per episode and custom `InfoEvent`s can be written from a loop that is not an Inspect task, round-trips through `write_eval_log`/`read_eval_log` in both `.eval` and `.json`, carries arbitrary metadata (the Harness Card), and supports header-only reads. The event classes have moved to `inspect_ai.event` (deprecation warnings in 0.3.x, removal in 0.4), and the sample model is single-model (`EvalSpec.model`, `model_roles` for several). Verdict: feasible and useful as an **export** (`simspec.export.inspect`), so that Inspect's viewer and `recompute_metrics` work on our runs; not as the primary format, because it would make a 100-package stack a hard dependency of a research library whose logs must stay `jq`-able and because our unit (episode with N seats, joint actions, rule events) is not Inspect's sample.
- **LangGraph as the loop**: a two-player alternating game as a `StateGraph` with `InMemorySaver` gives one checkpoint per node (8 for 6 steps) and `update_state` at a historical checkpoint followed by `invoke(None)`. Two findings: the serializer turned the `random` state tuple into lists (a type change inside checkpointed state), and the "fork" continued on the **same thread** and overwrote its head (the original thread's final state became the forked state); a true fork needs manual copying to a new `thread_id`. Replay re-executes nodes (agents are called again). Verdict: not adopted. The checkpoint shape (`channel_values`, `channel_versions`, parent, `metadata.step`) is copied as a design idea only.

Decision D-006 in `docs/decisions.md`: custom thin runtime (loop, vault, chance log, JSONL events, snapshots, replay-by-readback and forks), with an Inspect export adapter.

## 8. Where the brief's assumptions were wrong or incomplete

memo
- The repo is at 1.2.3 and broken on current JAX; upstream 1.3.2 is the usable version and adds array parameters, `forgets_about`, multiple returns, keyword args and `has_theory` variants.
- memo cannot host the environment loop at all (no sampling, no state); it is a per-decision oracle. The brief's "compiles to memo models while owning the multi-step game loop" option is the only viable one of the two offered.
- Array-valued parameters and `cache=True` are mutually exclusive, which shapes how generated memo code must be structured.

ContractSim
1. Exactly two players (Customer, Supplier); no multi-supplier or "firm" variant. "One supplier setting" in Phase 2 should be read as "one of the three settings (Catering)".
2. The protocol is asymmetric: only the Customer accepts, and only the Supplier's previous-round proposal; there is no reject/counter action, only replacement; 50 rounds = 100 turns; turn output is JSON.
3. The structured contract exists only in an offline LLM translator with a closed four-clause vocabulary; the negotiated artefact is free text; `ε = 0.05` fixed.
4. Timing is alternating payment/production weeks with a terminal trust-only payment; the Supplier sees prices before ordering; pays for ordered-not-received; cash and inventory caps bind.
5. RE is non-engagement, not a best response; RC uses a fixed production heuristic; performance is evaluated on synthetic contracts, not negotiated ones; there is no fairness metric; `U_i(ω)` is defined under joint RCC play.
6. No code or data release.

Norms paper
- The environment is a 23×22 Melting Pot substrate with Lua components, not a small gridworld; learners have full observability; other agents are static obstacles in each agent's forward model.
- Rules are Python boolean expressions over an observation dict; the deadline `τ` is a global constant, not per rule.
- Induction is mean-field with a bounded-compliance mixture likelihood built from planner Q-values with and without the rule; the expensive part is the planner, not the enumeration.
- No sanctions in the reported experiments; no LLMs anywhere.

Concordia
- 2507.08892 is the "game engine" paper, not the contest paper (2512.03318).
- Concordia v2 can be configured with no LLM in the control path, but only by hand-assembling ~14 components; it has no typed state, no run seed, and checkpoints do not give deterministic replay.

Decision models
- Jev's third primitive is Noul, not Boolean; OpenAI's is predicate. Both always return distributions for choice/score; the guard is needed for the Anthropic/Google adapters, not for the native endpoints.
- `/v1/decisions`-compatible gateways: LiteLLM, Vercel AI Gateway, Portkey, agentgateway, llmgateway.io; OpenRouter uses the TypeSafe schema at `/api/alpha/decisions`.
